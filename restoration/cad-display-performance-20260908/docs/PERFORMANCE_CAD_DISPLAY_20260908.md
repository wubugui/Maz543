# CAD 显示优化：已启用项、候选项及剩余瓶颈

用户要求优化已变得无法使用的网页预览，禁止通过减少功能、零件、几何细分或机械精度换速度。完整 MAZ‑543A 产品演示 goal 仍 ACTIVE，全部 16 项整车验收 OPEN。本阶段不是性能最终验收。

## 正常页面已经启用

1. 每个实际显示帧只更新一次阴影。颜色与 GTAO 法线通道使用同一机械姿态，后者复用该帧阴影。下一显示帧仍请求新阴影，没有跨运动帧冻结阴影。全车同帧读取 1212×773 RGBA：11,627 → 9,305 调用，26,978,281 → 21,582,915 提交三角形，差异像素 0、最大色阶差 0、两次 GL 错误码 0。减少的是重复通道工作，不是资产面数。
2. 保守的显示缓存：每次仍调用原有机械求解与姿态更新；以完整 JS 数值比较可见节点、相机、属性缓冲版本/身份、形变权重、材质和灯光，以及控制状态变更。没有坐标误差阈值。相同输入保留已绘制画面；修改、运动、显隐、相机、尺寸变化立即重新绘制。隐藏机构继续计算，重新显示时使用最新位姿。严格比较也意味着整车极小的悬架体姿变化会继续重绘；不能宣称整车已经进入低开销空闲状态。
3. 扭杆上一次显示角度完全相同时复用其现有变形缓冲；计算角度不同则仍完整更新全部顶点、法线和切线。
4. 相机聚焦和阻尼按经过时间缓动；原来按帧数缓动会在低 FPS 下拖很久。机械求解步长没有随之修改。
5. 原生 GLTF 资源所有权与释放：贴图随材质显式释放，关闭自有 ImageBitmap，处理组件卸载之后才完成的异步加载，释放阴影目标；全部原生模型解码完成后释放闲置 Draco 工作线程。此前 Material.dispose() 本身不会释放其贴图。本阶段尚未做浏览器长期内存斜率测量。
6. 状态条低于 10 FPS 时显示一位小数，静止画面复用时显示“画面已缓存”，避免把 0.4 FPS 四舍五入成 0 或将缓存命中当作高 FPS。

## CAD 方法及候选实验

Open CASCADE 的 AIS_ConnectedInteractive 将显示/选择表示与引用对象联系起来，以独立变换复用表示：[官方说明](https://occt3d.com/dev/doc/refman/html/_a_i_s___connected_interactive_8hxx.html)。本项目保留原零件节点、几何、名字、父子关系、位姿和导出，另建仅显示的代理根。选择射线仍查原零件。Three.js 的 [InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html) 用于相同几何；[BatchedMesh](https://threejs.org/docs/pages/BatchedMesh.html) 用于相同材质、不同几何并保留逐件视锥检查。

两个候选只在开发诊断入口启用，正常页面不创建这些缓冲：

| 试验 | 调用 | 提交三角形 | 画面比较 |
| --- | ---: | ---: | --- |
| 单次阴影基线 | 9,305 | 21,582,915 | 基准 |
| 328 件 / 16 个相同几何实例组 | 8,057 | 21,582,915 | 初次 25 像素不同，最大 1 色阶 |
| 1,906 个当前可见件 / 51 材质组 | 1,885 | 21,582,915 | 初次 307 像素不同，最大 59 色阶 |

材质批量缓冲覆盖 2,558 个几何，逐个核对 80,659,352 个属性分量与 18,507,990 个索引，0 不一致，未做简化或焊接。但 GPU 实例矩阵/计算次序、排序与边缘栅格结果不能等同于逐像素无差异。不得掩盖这些画面差异。

材质批量缓存增加 392,645,360 字节。热身后同帧同步读取：候选 1546.8 ms、基线 1553.5 ms，候选与基线画面有 335 个不同像素、最大 67 色阶。这不是可靠的持续 FPS 提升，也不足以支持默认启用。初次包含编译的候选 2938 ms 不能当稳态性能。完整原始 AX 记录保存在 outputs/render-performance-evidence，机器可读汇总见 outputs/render-performance-results.json。

## 浏览器事实与验证范围

当前 IAB 1 / tab 3 的应用报告 ANGLE Microsoft Basic Render Driver，WEBGL_multi_draw 可用。不能因系统列出了 GTX 970 就声称网页使用它。chrome://gpu 被浏览器 URL 安全策略阻止，未绕过该限制，也未修改系统、驱动、Codex 设置或端口。

正常整车仍约 0.4–0.8 FPS。两次普通整车点击受到 CDP focus-emulation 超时影响，不能当作操作通过。为单独测量静态机构，增加开发专用 `/?qa-focus=drive` 场景；它设置与变速机构检查相同的控制状态，不暂停任一求解器。该页真实显示“画面已缓存”，截图中模型正常；随后实际点击“行星齿轮”成功切换，再点击 START，状态进入启动机带转约 194 RPM、主油路 11.03 kgf/cm²，显示状态从缓存变为约 1.0 FPS。之后点击 STOP。具体记录见 cached-drive.png、cached-drive-ax.txt、cache-invalidated-by-start-ax.txt。开发场景初始化不证明此前超时的整车快捷按钮已通过。

`scripts/verify-display-presentation.mjs` 检查原节点选择身份、最新运动矩阵、父级隐藏/恢复、透明/剖切/反射回退、原始属性和索引不变；小构造场景实际 GLTFExporter 生成的 GLB 在显示优化前后字节完全相同。还检查严格缓存失效、替换/更新属性、相机/材质变化、共享资源只释放一次和晚到异步资源释放。它不是整车导出或长期内存验收。

TypeScript 检查已通过，生产构建日志为 work/render-performance-build.log。仅模型资源的当前哈希记录在汇总中，本阶段没有重导出或修改任何原生几何资产。

## 必须继续

- 整车动态画面仍慢，不能宣布用户的性能问题解决。
- 查清软件渲染使用原因需要允许的诊断路径；禁止绕过已被阻止的内核页面。
- 原有机械步进仍依附 RAF 且最多推进 0.05 秒，低 FPS 会使模拟时间明显落后于墙钟时间。后续应研究独立、固定精度的仿真调度/工作线程，并验证控制时序和已有 240/480 Hz 内部步进，不能通过少算物理来改善显示。
- 可进一步优化主线程响应、静态显示表示与遮挡处理；必须证明遮挡判断保守，透明/剖切/运动不漏件。候选合批目前不默认启用。
- 四工作轮变矩器、完整发动机、各机械系统精度、动力学、安装闭合及最终写实整车检查仍按完整 goal 继续。
