## 相同输入

实际 Three r183 GTAOPass 的 64×64 降噪纹理由 SimplexNoise 的随机源生成，独立上下文默认输入不同。`lib/contextFrameAudit.ts` 仅在开发 `inspect=context-audit` 下，用固定 RNG 调用同一 Simplex 算法和逐字节纹理生成配方，保留格式、采样、wrap 等设置。普通入口保持原随机纹理，没有修改 Math.random 或 Three 原型。

`verify-context-audit-noise.mjs` 将实际安装的 stock `_generateNoise` 配方在受控 Node 测试里传入同一个 RNG，核对全部 16,384 字节与新审计输入相同；独立构造的两组审计输入相同，旧自有纹理释放，原魔方噪声纹理保留。SHA-256 为 `292cffd4de183a1f5e30e4545f1152071ccf5ca50d7dccd5337eb7fd8e2e0722`。

## 有限捕获

审计按钮只请求下一完整姿态的一次 readPixels，记录原始 RGBA SHA-256、输入子集 SHA-256、实际源绘制顺序 SHA-256、噪声 SHA-256 和相机/尺寸/后台信息。不会把兆字节像素正文塞入对话。当前输入指纹覆盖矩阵、变形、材质子集和几何布局，明确不冒充全部几何字节或全部 shader 输入的证明。

## 实际装配失败与内存现场

主线程立体、侧视、侧视开门三帧已保存，GL 读回均 0 错误。切换到 Worker 后出现真实装配失败。原 `catch` 丢弃异常，只输出通用下载提示；首次补充 String(error) 得到 `[object Object]`。检查实际 DRACOLoader 源码，解码线程是用 `{type,id,error}` 拒绝 Promise，因此新增 `nativeModelError` 保留该结构的具体原因，并在各资产加载处附上资产 URL。普通用户提示仍简短，审计模式额外显示具体异常，控制台保留原始错误。

最终实际原因：`/models/maz543a-blender.glb?v=cab-profile-1: Array buffer allocation failed`。三份失败 AX 都保留，没有伪装成通过。全部 7 个当前原生 GLB 的 SHA-256 与不可变归档相同。

只读内存现场显示系统约 32 GiB RAM、约 4.5 GiB 可用；ChatGPT PID 19120 私有内存 28,938,686,464 bytes（约 26.95 GiB），工作集约 14.38 GiB。该数值是整个进程，不能当作单个模型的纯几何内存。关闭本任务已失败的 IAB 标签 3 后，PID 19120 确认退出；没有终止系统进程或其他用户标签页。新的完整 Worker 核对改在本任务 IAB 标签 6 进行。证据 `memory-before-close.json`、`memory-after-close.json`。

这证明巨大占用与该预览页面的生命周期关联，但尚未定位是历史页面保留、GPU/解码资源释放还是峰值分配的具体机制。[Chrome 生命周期文档](https://developer.chrome.com/docs/web-platform/page-lifecycle-api) 和 [bfcache 文档](https://web.dev/articles/bfcache?hl=en) 说明历史页面可能保留完整 JS 堆并冻结后台任务，这里只作为待核查路径，不把 bfcache 当作已证实根因。后续优先验证页面退出与资源保留，不在未证明原因时删减部件或重写解码精度。
