# Draco 解码器退出竞态修复

完整 goal ACTIVE，16 项整车门槛 OPEN。本阶段修复实际资源生命周期问题，不删减部件、细分、贴图、采样或机械计算。完整动态整车的低帧率仍未解决。

## 实际来源与修复

安装中的 Three r183 DRACOLoader.dispose 只终止当前 workerPool 并撤销当前 Blob URL。若 `_initDecoder` 仍在等待解码库，稍后完成时仍会创建 Blob URL 和 Worker；正在等待解码的回调也不会由原 dispose 主动拒绝。

`lib/ownedDracoLifetime.ts` 对本查看器持有的加载器实例加退出保护，不改 Three 原型、解码库、任务配置、压缩精度或两个线程的并发上限。退出后拒绝新任务、已有等待任务和原生 Worker 回调；延迟初始化完成后撤销其自有 URL，阻止迟到 Worker。线程已取得但解码尚未提交的微任务间隙也有保护，防止向已终止线程提交并永久等待。成功任务仍由原始 `_createGeometry` 构造原始几何。

内部接口在入口检查，升级 Three 时必须重新验证。只处理本实例的解码资源，没有取消共享网络请求或修改历史页面缓存策略。

## 有限验证

`scripts/verify-owned-draco-lifetime.mjs` 使用实际安装的 DRACOLoader 控制流，只有解码库传输和 Worker 传输受控。先复现原实现 dispose 后创建活线程，再验证保护后无迟到线程、活动任务拒绝、回调清空、提交间隙退出、重复释放和新任务拒绝。成功样本通过原构造器保留三顶点及索引值。报告 `outputs/owned-draco-lifetime/tests.json`。

TypeScript 和生产构建通过；此前类型检查发现 postMessage 重载参数范围过窄，已修正为兼容 transferable 数组和 options 的原始重载输入。

实际完整 Worker 在热更新后装配成功；随后普通 `http://localhost:3000/` 入口加载成功，显示 8868 登记实例、静止画面缓存、独立计算 240 Hz、积压 0.000 s。普通截图已保存并查看，车辆完整可见但初始视图较小，不能作为全部机械结构验收。11 个机械/导出文件、16735 字符整车姿态更新块和质量配置与此前不可变归档相同；七个原生 GLB 已核对相同 SHA-256。
