# 保守空间依赖与形变范围实验

完整 goal ACTIVE，整车 16 项验收仍 OPEN。模型、机械计算、导出和显示质量未降低。`inspect=occlusion-tile-audit` 为开发实验，普通预览不启用；当前动态性能仍未解决。

## 从工业 CAD 显示方式中采用的原则

Open CASCADE 把持久内容和即时交互内容分层，并使用包围体与视锥判断减少提交；复杂透明和剖切又有独立通道成本。本项目保留完整写实通道，采用缓存依赖与保守可见范围，未采用尺寸剔除、距离剔除或降低采样率。[Open CASCADE：TKOpenGl Frame Render Graph](https://www.opencascade.com/blog_tag/visualization/)

空间边界不是模型精度。`conservativeRasterBounds.ts` 只估计一个原始绘制可能影响的屏幕范围，不改顶点、不裁三角形，也不直接把离屏包围体视为不可见。仍只有原始 GPU 查询为零、目标自身深度输入完全相同、覆盖到的全部区域之前的深度序列也完全相同，才省略原绘制。

## 实现与回退

深度序列按 32 像素区域记录，保留原有逐项比较与无碰撞序列 token。每个原始目标、实际 viewport、深度附件、4/2/0 采样通道独立，阴影不参与剔除。运动目标自身必须重新绘制；不因上一帧不可见就隐藏运动零件。

范围读取全部 Float32 position，不信任外部 boundingBox，不收缩到 drawRange。变换使用实际 Float32 矩阵输入，按区间向外扩张，覆盖乘加重排、FMA 与次正规值归零，并为投影、窗口运算和覆盖采样保留余量。眼平面/近裁面不确定、非有限值、其他存储类型及未知着色器回到全屏依赖或完整绘制。[Khronos GLSL ES 3.00 §4.5.1](https://registry.khronos.org/OpenGL/specs/es/3.0/GLSL_ES_Specification_3.00.pdf)、[OpenGL ES 3.0 §2.13](https://registry.khronos.org/OpenGL/specs/es/3.0/es_spec_3.0.pdf)

弹簧同时覆盖相对/绝对 morph 的全部当前权重，跟随本地 Three r183 的实际计算式。该版本只在目标数量变化时重建 morph 纹理，不随属性版本更新，所以修改过 morph 源的情形不使用局部范围，避免把新的 CPU 数据误当成当前 GPU 数据。

最终加入每帧最多 250000 次区域访问与历史节点预算。超过预算恢复剩余原绘制，不减少部件。未知深度写入使该通道剩余部分不再构建证明，剖切不再无效累积大量区域历史。400 个附加对象的预算用例验证所有 402 次原绘制保留。历史仍按 16 帧或总量阈值重建。

## 实际完整模型结果

ANGLE Microsoft Basic Render Driver，1212×773，完整 UI 登记 8868 实例。以下每对共享同一场景、相机、姿态与原渲染输入；全部读回错误 0、不同像素 0。表中时间含同步读回，不能作为持续 FPS。

| 工况 | 跳过 draws | 候选 / 原始 draws | 候选 / 原始毫秒 |
| --- | ---: | ---: | ---: |
| 静止预热 | 5231 | 4074 / 9305 | 1052.5 / 1307.4 |
| 发动机约 547 RPM | 150 | 9155 / 9305 | 1458.4 / 1465.1 |
| 侧视、右前门 99°、发动机运转 | 67 | 9239 / 9306 | 1284.0 / 1260.2 |
| 一挡、约 529 RPM、演示 3.4 km/h | 57 | 9249 / 9306 | 1284.8 / 1271.8 |
| 纵剖、一挡、开门 | 0 | 9139 / 9139 | 1255.2 / 1234.1 |

发动机只省 204720 个三角形，原整帧 21582915 个。开门和一挡样本反而稍慢。静态大幅省绘制也不能当成普通静止入口新增收益，因为普通入口已有整帧缓存。加载顺序会影响可复用数量，各次加载只做同上下文配对，不跨加载比较像素或宣称顺序相同。

独立的 12 帧发动机记录没有同步读回，平均绘制线程工作 1126.48 ms，平均帧起点间隔 1338.26 ms；每帧跳过 0–152 次，累计查询 1892 次，发生一次历史重建，记录最大 100240 个历史节点，机械积压最大 0。没有同批连续基线，不能据此报告百分比提速。界面仍约 0.6–0.8 FPS。

支持 morph 范围后，三个通道全屏范围从 285 个降至 3 个，区域访问从约 288000 降至约 20950。然而发动机运动件和内部静止件大量覆盖相同屏幕区域，仍约 6200 个原始查询位置每帧前序变化。该方案没有取得足够的动态收益，因此保持默认关闭。

早期 `warm-final.json` 实际记录的是发起查询的帧，不代表已复用；有效静态证据是 `warm-verified.json`。早期动态配对有历史重置、跳过 0 的记录，保留原始证据，最终用 `engine-verified.json` 记录确实跳过 150 次的配对。组合诊断的两个按钮原先位置重叠，已把 12 帧按钮移到独立位置。

## 验证与继续方向

受控测试包含 90000 个普通浮点变换顶点、4800 个相对/绝对形变顶点，全部位于向外扩张范围内；目标/前序微小运动、进入相邻区域、材质精度、未知 shader define、属性更新、近裁面、待完成查询、失败释放、上下文及预算回退通过。这些 CPU/受控查询用例不冒充 GPU 编译器或完整光栅证明，真实整帧结果另列如上。

最终类型和构建通过。11 个机械/导出文件、16735 字符姿态块及质量配置仍同不可变基线。预算保护加入后另取实际复用配对，记录在 `post-budget-pair.json`；普通预览在取证后恢复。

下一步需要调查由稳定车体/外壳提供遮挡证明的方法，避免内部运动件成为静止内构的前序依赖。候选方向是单独的静态遮挡深度与向外扩张的查询体，仍须处理目标自身深度、透明、采样、矩阵精度、额外存储和动态失效；尚未实现，不可据此声称完成 CAD 显示优化。完整机械目标不缩减。
