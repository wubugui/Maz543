# 原程序提交位置的实际遮挡复用

完整 goal ACTIVE，整车 16 项验收 OPEN。此阶段首次把原透射、主颜色、法线三个通道的精确程序深度证据用于真实几何提交。DEV `inspect=original-program-occlusion-audit`，默认关闭。完整机械、建模精度和可用动态性能尚未完成。

## 实现与失效条件

`lib/originalProgramOcclusionCache.ts` 建立一代静态遮挡体快照和异步保守体查询。快照沿用已验证的原链接程序重放，每个通道保持自己的实际 MSAA、24 位深度和 viewport。控制查询全部可用并通过后，才接受零采样体。

每次产品绘制仍执行原 `renderBufferDirect`，保留程序选择、材质、原矩阵和 uniforms 上传。在原 WebGL `drawElements` / `drawArrays` 即将提交 TRIANGLES 时，才检查实际刚选中的程序包装对象与捕获的原链接句柄。旧的 material.currentProgram 不能提前当作证明。只省略证明覆盖的三角形调用，并精确扣除 Three 统计中未真正提交的 calls/triangles。

阴影相机、透明材质、非三角形、自定义回调和不支持的路径全部保留原调用。未改变任何原 Mesh.visible、几何、机械状态、求解频率或显示质量设置。

静态遮挡体的精确几何属性、版本、世界矩阵、形变、层、包围球、材质配置改变时，整代证据失效，已变化遮挡体退出当前静态集合。相机、目标配置/尺寸、viewport、场景/灯光/材质程序配置或链接句柄变化同样失效。候选体离开先前证明范围即恢复原提交。当前实现每代一次查询，离开范围后不追加查询；因此动态剔除数会波动，不以冻结部件换命中率。

材质签名包含不一定增加 version 的数值、纹理和向量配置；未知配置回退。移除的候选释放程序/证书引用，几何/材质/目标 dispose 使缓存失效。控制失败、查询未完成、上下文丢失均不剔除。所有 GL/Three 临时钩子在成功和异常后恢复。
