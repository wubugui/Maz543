# 静态车体深度与保守查询体

完整 goal ACTIVE，整车 16 项验收仍 OPEN。本阶段实现有限开发诊断，普通预览不启用，没有省略任何产品绘制。结果证明该方向有可观潜力，尚不证明实际提速或可安全跨帧剔除。

## 本次改变

`inspect=static-occlusion-probe` 观察完整原生模型相邻帧的几何、属性版本、世界矩阵、相机、形变权重及深度材质输入。连续两帧相同的部件只作为当前快照的候选遮挡体，不据此断言以后不动。相机改变、微小的有效世界矩阵变化、属性和形变变化都会重新开始观察。

诊断构造自有 Mesh 和法线材质，原始几何/属性/索引只读共享，世界矩阵与形变权重独立复制。按真实 4/2/0 采样模式建立独立深度目标，保留完整三角形、原始面朝向、可见材质分组和 drawRange。不改变源模型、源材质、源姿态、阴影或最终产品画面。

直接把被查对象绘进深度后再查询同一表面会有自身深度问题，因此查询使用包住全部原始几何的屏幕矩形，并把查询平面放在所有原始/形变顶点最近深度之前。透明、裁剪、位移、未知 shader、线框和其他不支持的路径不作为普通不透明遮挡体。

## 关联深度范围

首次把 z 和 w 独立取范围，得到的平面过于靠前。静态 2 采样目标只有 231 个零查询体、41308 个对应三角形，不能据此否定几何可见性缓存。

最终 `ConservativeRasterBounds.volume()` 使用原始位置/形变局部范围的八角点。先计算覆盖每个着色器结果的共同向外误差盒，再保留每个角点 z/w、x/w、y/w 的关联。正 w 时，线性分式在这个凸包上的极值由顶点界定；相机近面、非有限输入等仍回退。Float32 输入、乘加重排、可能的次正规值归零、投影、窗口运算、深度量化与采样边缘都保留向外余量，不改变模型精度。此前空间前序缓存的二维范围计算保持原算法。

范围计算依据本地 Three r183 的矩阵/形变实现及 [GLSL ES 3.00 浮点约束](https://registry.khronos.org/OpenGL/specs/es/3.0/GLSL_ES_Specification_3.00.pdf)。90000 个普通顶点与 4800 个相对/绝对形变顶点的受控浮点计算均位于范围内，查询深度均在它们之前。这些 CPU 检查不代替真实 GPU 着色器/光栅验收。

## 实际完整浏览器结果

ANGLE Microsoft Basic Render Driver，1212×773，完整登记 8868 实例。各目标实际采样为 4、2、0，深度均 24 位。每个目标都有独立的近面必过/远面必失败控制查询，全部六个控制通过。

| 工况 | 当前稳定遮挡体 / 运动或新对象 | 2 采样零查询体 | 对应三角形 | 原产品显示像素差 |
| --- | ---: | ---: | ---: | ---: |
| 静止，旧独立 z/w 范围 | 2315 / 0 | 231 | 41308 | 0 |
| 静止，关联角点范围 | 2315 / 0 | 1938 | 3302030 | 0 |
| 发动机约 548 RPM | 1934 / 381 | 1938 | 3302030 | 0 |
| 侧视、右前门 99°、发动机运转 | 1934 / 381 | 1966 | 3274918 | 0 |

发动机工况的零查询体包括 1566 个本帧观察稳定对象和 372 个运动对象。运动对象的结果仅适用于当前快照，不能直接拿到下一帧。4/0 采样工况也分别得到约 327/330 万个对应三角形。这里的数字是查询潜力，不是已经节省的绘制或三角形。

发动机快照使用 1934 次深度绘制、4236729 个完整三角形/目标。一次三目标快照及查询提交约 2624 ms，临时目标估算 67455072 bytes（不含驱动分配细节）。如果每帧重复此诊断，会明显增加负担；只有后续正确复用证明和静态深度才有可能产生净收益。当前仍约 0.5–0.6 FPS。

侧视、右前门 99°、发动机运行的独立重建另存于 `side-door-correlated.json`，统计与校验汇总见 `summary.json`。诊断前后产品帧读回差 0，仅证明诊断没有改写产品帧；这不是实际剔除后的像素验收。

## 资源与界面

查询结果只在 AVAILABLE 后读取，不忙等或 gl.finish。成功、绘制失败、上下文中断和销毁路径释放自有查询与三个渲染目标。恢复原渲染目标、颜色/深度写掩码、清除值、阴影更新标志和渲染函数。自有 Mesh/材质销毁不 dispose 共享原几何，受控资源测试通过；不将 API dispose 等同于操作系统已经返还内存。

完整查询 JSON 约 1.3 MB。首次直接放在可见 pre 中导致浏览器检查出现超时；同一次任务随后成功读回，未因超时重启实验。最终改为可见摘要与隐藏的原始结果节点 `pre[data-static-occlusion-results="1"]`，保留全部记录并避免巨大文本布局/可访问性树负担。

类型、构建及针对性范围/观察/资源测试通过。11 个机械/导出文件、16735 字符姿态块与显示质量配置同不可变基线。普通预览在取证后恢复。

多轮重载后的诊断标签页在全部查询完成、原始结果保存后关闭。进程快照显示 PID 40004 的私有占用为 13878161408 bytes，关闭本任务自有标签页 7 后该进程退出；没有杀进程或改动其他浏览器标签。新的普通标签页 8 恢复 8868 实例、画面缓存、240 Hz/零积压。这不能证明多 GB 保留由本次约 67 MB 临时目标造成，持续内存归属仍未解决；原始快照见 `process-*.json`。
