# 保留原索引顺序的三角形范围遮挡

完整 goal ACTIVE，整车 16 项验收 OPEN。DEV `inspect=triangle-range-occlusion-audit`，默认关闭。此阶段没有重建、简化或减少任何权威部件几何，只在原着色程序的提交位置省略已证明不可见的连续索引范围。

## 范围数据及正确性边界

此前整件查询中，八个轮胎各 126804 个三角形均为正采样/未证明；整件包围体无法区分局部被遮挡的部分。`triangleRangeProxies.ts` 对连续原索引范围收集所引用 Float32 顶点的精确极值，用八个角点编码 CPU 包围数据。无形变范围仅 96 字节，当前完整车辆 10 个大网格共 900 个范围、86400 字节。这些数据不进入场景、不上传 WebGL、不参与导出。

范围保持原始三角形顺序及原组边界，支持非索引和交错位置属性；形变使用各原属性范围及既有 Float32 运算误差界。每代最多查询 4096 个范围，预算不足直接保留原绘制，不调整细节。未知数据、修改过的原 morph 属性、异常索引、未对齐组等回退。

固定重启索引不能按原始元素数模三切分，因此 Uint16 的 65535 / Uint32 的 4294967295 均拒绝，即使该数值在顶点属性范围内。当前 Three r183 `src/utils.js` 的 arrayNeedsUint32 同样显式处理 PRIMITIVE_RESTART_FIXED_INDEX。

每个范围在透射、颜色、法线自己的原程序静态深度快照上查询。它们与整件查询结果分开保存；报告中的整件/范围零采样总数可能重叠，已明确标记 `zeroCountsOverlap`，不能相加当作实际节省。

真正绘制仍执行原程序选择和原 uniforms 上传。在原 `drawElements` / `drawArrays` 位置验证刚选择的链接程序，先尝试整件证书，再验证每个范围当前体仍被覆盖。可见范围按原顺序合并；索引调用使用原索引类型与精确字节偏移，非索引调用保持原 first，使顶点身份和三角形顺序不变。没有 Mesh.visible 切换或替换 GPU 几何。

拆分可能增加调用数。统计同时扣除省掉的三角形、加入额外的小调用；不把一个拆成多个调用伪装成调用减少。相机、静态遮挡体、材质、目标或原范围属性变化使整代证明失效，资源释放时只释放自有包围数据。

## 实际验证

完整 8868 实例，IAB / Microsoft Basic Render Driver / 1212×773；实际 MSAA 4、2、0，深度均 24 位。最终静止验证实际省去 9755810 个三角形，其中范围细分额外省去 1478620；25 个原调用变成 80 个小调用，整帧 9305 → 3983 次提交，像素差 0。六个控制通过，WebGL/readback error 为零。

发动机约 549 RPM 的最终配对帧总计省去 8620266 个三角形，其中范围额外省去 1226716；19 个原调用变成 64 个小调用，整帧 9305 → 4509，像素差 0。机械计算保持 240 Hz、零积压。

侧视开门、纵剖回退与连续动态对照完整结果见 `outputs/triangle-range-occlusion/summary.json`。性能只由构建结束后的连续帧窗口评估；单帧读回时间受同步及邻近构建负载影响，不作为纯 GPU 时间或稳定提速结论。
