# 独立显示的资源清理与故障恢复

2026-09-09。完整 goal **ACTIVE**，16 项 **OPEN**。上一轮静止整车缓存已经生效；本轮修复失败路径造成的资源残留，并验证故障后能重新装配完整车辆。没有据此关闭动态整车性能、机械标定或默认 Worker 的全部门槛。

## 问题与实现

旧 `createRenderWorkerClient` 先创建画布和两个 Worker，再转移 OffscreenCanvas。第二个构造、消息通道、画布转移或后续注册出错时没有回滚。Worker 的 onerror 仅报告文本，机械线程、DOM、监听和待执行 RAF 仍可能存活；退出时 dispose 消息发送失败也会跳过兜底终止。

现在资源获取放在同一个异常处理范围，按实际已获取的资源清理。同步异常移除自有画布/覆盖元素，终止自有线程，关闭通道、断开观察器、释放指针捕获、移除监听、取消 RAF，拒绝未完成的 API/导出请求。清理中的单个异常不会阻止其他资源处理，会保留日志。仅在 api 仍属于当前客户端时清空，旧客户端不能抹掉新实例的 API。

正常卸载保留原有 GPU 资源释放机会：先停止机械线程和主线程监听，向显示线程发送 dispose，收到确认后终止；无确认则最多 10 秒后仅终止这个自有线程。发送 dispose 本身失败时立即终止。致命故障使用立即终止路径，避免等待已经无法处理消息的线程。此处未修改系统进程、其他标签页或浏览器设置。

新增 `fatal` 消息，与可恢复的 `error` 区分。显示初始化抛错、无有效运行时、完整模型加载失败和未处理的 Worker 消息错误触发致命清理；非致命提示保留原路径。机械 Worker 崩溃/解码失败也结束这个失效实例，不能继续显示虚假的 240 Hz 工作状态。

同步启动失败在回滚完成后使用新的普通画布和原有完整渲染器。异步运行故障不会自动重建求解器、悄悄重置机械时间。`Workshop` 撤下失效的部件/导出状态和旧的绘制/计算状态；点击现有“重新加载”或“重置模型”后才清零控制和遥测并在同一页面重新挂载车辆组件。正常实例的“重置模型”继续使用原有机械复位，不额外重建场景。

普通用户错误信息使用简短原因，开发控制台保留异常细节。模型不可用时显示“模型未就绪”。只在开发参数 `worker-lifecycle=1` 下提供“开发检查：模拟显示故障”按钮，用实际显示 Worker 内的抛错验证恢复通路；普通和生产入口没有此按钮。

## 验证

`scripts/verify-render-client-lifecycle.mjs` 在实际客户端上注入确定性浏览器/Worker 模拟对象。9 个同步故障覆盖两个构造、通道、转移、监听、观察器、机械 reset/通道连接和显示 init；9 个运行故障覆盖两个线程的 error/messageerror、fatal、异常关闭、非法覆盖元素和控制发送失败。测试还检查正常关闭确认、10 秒兜底、dispose 发送失败、未完成导出拒绝、迟到消息、重复关闭、共享 host、新实例 API 及小数指针坐标。报告 `outputs/worker-lifecycle/client-tests.json` 通过。这不是硬件显存测试。

`scripts/verify-viewport-worker-failures.mjs` 使用实际 Worker 入口/host 协议和注入的构造器，确认初始化抛错及无 disposer 产生 fatal，资产失败为 fatal、可恢复提示仍为 error；正常 dispose 和释放中抛错均会关闭连接并确认结束。显示线程发生 fatal 后的实际终止由客户端负责，不能把该测试中的模拟端口关闭计数当成浏览器进程退出证据。

真实 IAB 标签页 3 的开发入口完成如下流程，原始 AX 和机器可读汇总保存在 `outputs/worker-lifecycle/`：

1. 完整装配 8868 个几何实例，静止画面缓存，独立机械计算 240 Hz、积压 0。
2. 点击开发故障按钮，在实际 Render Worker 的按钮回调中抛错。画布和诊断按钮撤下，导出和部件快捷入口禁用，旧“画面已缓存”和独立计算状态撤下，显示重新加载操作。
3. 点击“重新加载”，在同一页面重新挂载完整车辆；全部 8868 实例、导出入口、静止缓存和 240 Hz 计算恢复。AX 中只有一个车辆画布图像节点。
4. 重新装配后右前门实际打开到 99°，选择框和画面可见，之后重新缓存。实际截图已在任务工具输出中检查。

故障 AX 当时保留了旧形式的堆栈文本和“模型装配中”；随后只精简了错误文案并改为“模型未就绪”，错误协议和恢复逻辑不变。最后移除故障查询参数，保留可选完整 Worker 的正常预览。真实验证是单次受控异常及恢复，不是 GPU 驱动崩溃、长期循环泄漏测试或动态帧率提升证据。

`scripts/verify-worker-lifecycle-integrity.py` 对照最新适用的不可变归档，11 个机械/导出文件逐字节相同（包含上一轮已修正的悬挂版本），完整姿态更新区段 16735 字符相同，渲染质量配置相同。未改几何、贴图、阴影质量、机械步长或导出载荷。

最终 `tsc --noEmit --incremental false`、`npm run build` 均退出 0。构建仍提示四条路由的静态分类不完整，未把构建通过当成生产浏览器验收。

## 继续事项

完整 Worker 仍是开发参数，没有默认启用。仍需验证普通卸载的真实 GPU 资源回收、多轮切换、生产入口、视图尺寸/标签/实际拾取/剖切和跨上下文完整像素一致性；动态整车绘制仍慢。浏览器内核/驱动的挂死恢复也没有由受控消息错误测试证明。

继续围绕原始整车产品演示目标进行保精度显示优化，以及外形、内构、每个部件的动力学、物理标定和联动实现。失败清理只是预览能够可靠工作的必要部分，不代替这些工作。
