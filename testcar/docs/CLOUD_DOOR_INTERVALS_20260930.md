# 四门对新增前部件：连续角区间的保守几何检查

本轮直接读取当前生产 Master，四个真实铰链各11个子几何，对既有34个
`BL_Front_*` 部件共1496对，在0–99°整个闭角区间上都取得了充分分离条件。
没有依赖每3°的离散角度来填补中间状态，也没有保存或替换生产母版。
该结论只针对下述固定场景和刚体几何；全部16项整车验收仍OPEN。

## 方法与实际范围

沿用原 `hub-front-door-sweep-body.py` 的四个铰链、子对象选择与旋转方向。
直接取得frame 0实际求值网格顶点，通过真实铰链矩阵写成每个顶点的
`C + A cos(theta) + B sin(theta)`。计算每一坐标在整个闭区间内的端点和
内部极值，再取全部顶点的包围盒。任意三角形内部都是当时顶点的凸组合，
因此同样被这个包围盒包含。与固定件包围盒在至少一轴严格分离，即是
该对冻结刚体几何在整个区间不相交的充分条件；包含在另一实体内部的
情况也不可能通过这种包围盒分离条件。

实现支持递归缩小角区间；达到深度或工作预算但仍重叠时一律UNRESOLVED。
实际1496对在完整0–99°区间的首次包围就已分离，无需递归。本轮最小轴向
分离下界为0.106174748 m；后门对应最小下界0.874309615 m。这不是精确
最近表面距离，也不是原厂设计间隙或制造精度。

每个移动/固定包围盒各向外扩20 µm；极值角是否落入区间的比较再向外扩
1e-12 rad。使用Float64解析计算，没有声称对Blender/WebGL每个浮点运算
做形式化区间算术证明。结论是保存输入几何的理想刚体运动，并显式保留
上述数值余量和范围。

## 原生对应与依赖检查

独立使用真实Blender铰链操作检查0、0.731、14.37、48.125、83.61、99°，
全部顶点对应数量相同，公式与实际求值顶点最大差0.226122 µm。这个检查
仅确认实现与实际轴/坐标对应，不是连续区间结论的替代依据。

移动对象、父链、几何数据的动画/约束/形态键及外部曲线引用均检查；未知
修改器会使依赖判定未决。固定前部件初检有Boolean和几何节点，不能只因
六个角度没变化就当成恒定。进一步逐项检查得出：

- 六个Boolean操作数均为静态、未挂在任何移动门层级下的对象；其父链、
  几何、修改器依赖同样受检查
- 四个风挡部件及两个胶条裁切体的位置映射组仅含局部Position、SetPosition和数值组合
  运算，没有对象/场景输入、嵌套组或动画。完整节点类型记录在报告中
- 所有检查角度结束后，34个固定件的实际求值几何逐值保持；全部原生依赖
  清单满足本次受支持的刚体/静态条件

这不覆盖运行时任意脚本、未来修改后的依赖图、其他帧或其他机构操作。

## 负对照与边界

独立构造一个真实体积的小立方体：0°与3°两端均与固定盒分离，1.5°时
整个小立方体进入固定盒。检查器拒绝给该完整区间分离证明，保持UNRESOLVED。
另验证完整一周的远处分离、内部三角函数极值、预算耗尽不得通过，以及
随机系数的密集回归。测试通过不替代上述解析包围推导。

本轮未检查原驾驶室壳、内饰、原车架、其他门之间和其余整车部件；未检查
当前网页实际加载/铰链操作，也未检验原厂尺寸、软性胶条形变或受载变形。
不能将1496对充分分离提升为“四门对整车全程无碰撞”或用户验收。

## 复现

在仓库根目录，用官方Blender 4.5.13运行
`blender --background --threads 4 --python-exit-code 1 --python testcar/scripts/audit-door-interval-clearance.py`。
输出仅写到`testcar/work/cloud-door-continuous-20260930`；脚本会核对生产Master
SHA256 `0391bfde5b7474a5f1ac4eac955f2fd8dbbb6febd33fb7d772a2cd18575edec3`
且从不保存blend。纯数值对照可用Python和NumPy运行
`testcar/scripts/door_interval_bounds.py`。
