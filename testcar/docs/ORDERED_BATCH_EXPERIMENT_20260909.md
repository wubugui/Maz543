# 保持原部件绘制顺序的合批实验

2026-09-09。完整 goal **ACTIVE**，16 项整车验收仍 **OPEN**。本阶段实验只由开发参数 `inspect=batch-ordered-audit` 启用；普通预览继续使用上一阶段已验证的定向阴影缓存及完整帧缓存。

## 问题与修正

检查实际 Three r183 `WebGLRenderLists.js` 与 `WebGLRenderer.js`，确认不透明对象先按 groupOrder/renderOrder，再按材质 ID、variant、投影 z、对象 ID 排序。旧精确矩阵合批克隆材质，克隆获得新的材质 ID，因此可能把原本先画的表面排到后画。`scripts/verify-ordered-batches.mjs` 用实际 r183 render list 复现了红/绿共面材质排序翻转；这是具体的排序问题，不仅是推测浮点误差。

新 `lib/orderedBatchDraws.ts` 仅为显示副本保留原材质排序键。批内使用原始 mesh 的 JS matrixWorld、原始 boundingSphere 和 r183 相同的 Vector4 变换顺序计算 z，不把 Vector3 透视除法或纹理内 Float32 world matrix 当作原排序输入。主视锥也直接测试原始 mesh。阴影批内顺序依据原场景遍历顺序。

一个材质只有在全部可见原始绘制都能归入同一个兼容批次时才合批；不完整材质组、动态变形、特殊变换、非零父组顺序等保持原对象绘制，以免与其余源绘制交错。全局跨材质排序仍使用原材质 ID。原始父子结构、部件 ID、选择命中对象、全部几何属性和导出继续保留。

这是一项保守的显示优化资格判断，不会隐藏退出批次的部件，也不会删减机械动画、内构或几何精度。旧合批/精确矩阵实验仍保留独立开发参数，新排序未改写普通预览的排序规则。

完整复制检查均为 0 属性/索引差，GL 读回错误均为 0。第三版逐分量比较 20,693,724 属性值和 5,807,769 索引，759 个不同源几何；这些包含当前隐藏模式的源对象，不能把复制几何数误当作当前可见实例数。

每一行都对应一次实质代码变更：先修正顺序与原始视锥，再避免分配不可能完整排序的分组，随后避免给含非兼容原始成员的材质组分配副本。原始 AX/JSON 保存在 `outputs/ordered-batches/whole-*-*`。不同版本实际参与合批的对象集合发生变化，不能据此把旧 332 像素差全部归因于单一排序修正。

初始捕获包含 shader 编译，同步耗时也包含 readPixels，不能据此声称稳定 FPS 改善。合批额外缓冲仍然显著，必须验证实际收益后才考虑启用。

## 预热与不同姿态

最终 486 实例 / 30 批次版本预热后，同姿态候选 1707.0 ms、基线 1731.9 ms，差距很小；换成侧视并打开右舱前门后，候选 1890.7 ms、基线 1766.5 ms，候选更慢。两个对照仍都是 0 不同像素、0 GL 错误，三角形完全相同。侧视开门多一次选中组件线框绘制，候选 7482、基线 9306。

这些顺序、同步读回的小样本不支持稳定速度提升。基于当前 Microsoft Basic Render Driver 后端的实际收益与约 104 MB 额外缓冲，本方案保持开发实验状态，不默认启用。不能用减少了 1824 次绘制来代替帧率证据。此前版本的 393 MB/152 MB 记录仍保留，并未覆盖为较好结果。

完整车辆上的两种姿态相同像素，证明该样本的显示结果一致；尚不构成全部视角、全生命周期、全部机械动作或跨硬件验收。后续可针对提交与 shader 纹理读取成本分开研究，再决定是否采用；本阶段没有断言剩余成本全部来自某一个因素。

## 验证与边界

`verify-ordered-batches.mjs` 验证实际 r183 列表排序、批内实际间接绘制表、原始视锥、阴影批内遍历顺序、材质组完整性退回、源对象选择与真实 GLB 字节一致。拆分布局材质组不分配副本，原始 mesh 仍保留。运行时对 r183 draw index 做显式校验；目前 @types/three 的排序回调声明缺少该字段，按实际源码加了受检类型适配，初次类型错误日志保留在 `work/ordered-batches/types.log`，最终检查在 `final-types.log`。

`verify-ordered-batches-integrity.py` 核对 11 个机械/导出文件、16735 字符的整车姿态更新块与最近适用归档完全相同，原显示质量设置未改。完整原车参数标定、各机构动力学和 16 项整车 gate 仍未完成。

最终排序/源数据测试、类型检查、源完整性检查和构建均退出 0；构建仍有既有的 vinext 路由静态分类提示，不能将构建成功解释为整车验收完成。
